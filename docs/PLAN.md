# План: «Дело «Ирбис»» — игра-учебник по KQL

> Итог реализации отличается от первой версии плана в двух местах (обе правки найдены тест-матрицей):
> сервер собран под **net9** с **KustoLoco 1.4.9** (у последней сборки под net8, 1.1.4, нет has/in/between/mv-expand/arg_max),
> а BabyKusto вынесен в отдельный `AssemblyLoadContext` со своей Kusto.Language 11.3: на 11.7+ он молча ломается
> (`sort … desc`, `$left/$right`). Актуальная таблица поддержки и список уровней — в README.

## 1. Архитектура и ограничения

* Один процесс ASP.NET Core 9 (`net9.0`, minimal API), `dotnet run` поднимает API и раздаёт собранный фронтенд из `wwwroot`.
* Движки KQL реализуют интерфейс `IKqlEngine` (`LoadTable`, `Run`, `GetSchema`):
  * `BabyKusto` — `BabyKusto.Core 0.1.8-preview`, используется по умолчанию;
  * `KustoLoco` — `KustoLoco.Core 1.4.9`.
* Оба движка зависят от `Microsoft.Azure.Kusto.Language`, но разных версий: хост и KustoLoco используют 12.4.1,
  BabyKusto — свою копию 11.3 в изолированном контексте загрузки. Контракты между ними не содержат типов Kusto.Language.
* `Kusto.Language` используется только для анализа текста запроса: диагностика с позициями, отказ от управляющих команд, разбиение конвейера на стадии по синтаксическому дереву (`PipeExpression`), схема. Свой парсер и интерпретатор KQL не пишутся, неподдерживаемые операторы не эмулируются: ошибка движка показывается как есть.
* Таймаут 10 с: запрос выполняется в отдельной задаче, ожидание ограничено `WaitAsync`. Движки не принимают `CancellationToken`, поэтому вычисление, превысившее лимит, дорабатывает в фоне, а клиент сразу получает ошибку.

## 3. Мир и данные

Компания «Стеклянный Маяк» (домен `mayak.corp`), 5 таблиц, генерация с фиксированным seed.

**Время.** Мир «привязан» к началу текущих суток UTC. Данные покрывают 30 предыдущих дней. Иначе `ago()` и `now()` на исторических данных ничего бы не находили. Содержимое детерминировано, сдвигается только календарная дата. В текстах уровней и эталонах даты записываются плейсхолдерами `{{D-2}}` (дата `yyyy-MM-dd`), сервер подставляет их при отдаче уровня. Текущая «дата мира» показывается в интерфейсе.

| Таблица | Строк | Колонки (тип) |
|---|---|---|
| `Employees` | 5 000 | EmployeeId string, Name string, Department string, Title string, Email string, Office string, Floor long, HireDate datetime, IsContractor bool, PerformanceScore real, Profile dynamic |
| `NetworkLogs` | 50 000 | Timestamp datetime, UserId string, Host string, SrcIp string, DstIp string, DstPort long, Protocol string, Url string, Action string, BytesSent long, BytesReceived long, DurationSec real |
| `EmailEvents` | 20 000 | Timestamp datetime, MessageId string, Sender string, Recipient string, Direction string, Subject string, Url string, HasAttachment bool, Attachments dynamic, Headers string (сырой JSON), SpamScore real, SizeBytes long |

**Сюжет и заложенные улики** (D-N означает N дней назад):

1. D-6, 10:00–10:40: фишинговая рассылка с `it-support@mayak-helpdesk.net`, тема «Срочно: подтвердите пароль VPN». Письмо получают 37 сотрудников, в заголовке `X-Originating-IP` у всех писем адрес `198.51.100.23`.
2. Ссылку открыли 4 сотрудника (`NetworkLogs`, `Url` содержит `mayak-helpdesk.net/reset?user=…`). Один из них, Глеб Штерн (E04217, отдел «НИОКР Ирбис»), ввёл пароль.
3. D-2, 02:07–02:51: вход в VPN под E04217 с внешнего `198.51.100.23`, чтение `fs-irbis` и выгрузка ~2,3 ГБ на `203.0.113.77` (`files.dropzone.example`).
4. Бейдж Штерна последний раз вышел в D-3 в 19:04, в здании его ночью не было.
5. Подрядчик Кирилл Лосев (E03981) за неделю до утечки 5 раз получил отказ у двери «Лаборатория Ирбис».
6. D-9: корпоративная карта Лосева оплачивает `CloudNest VPS`, в `Details.invoice.ip` указан `198.51.100.23`. Это замыкает цепочку.

Фон: обычный трафик, рабочие письма, проходы, покупки с суточной и недельной сезонностью. Все IP-адреса взяты из документационных диапазонов (RFC 5737), домены — `.corp` и `.example`.

## 5. Проверка ответа

Режимы в YAML (`check.mode`):

* `set` (по умолчанию) — мультимножество строк. Колонки сопоставляются по имени без учёта порядка; если `ignoreColumnNames: true`, то по позиции.
* `ordered` — то же, но с учётом порядка строк.
* `scalar` — одно значение (первая ячейка единственной строки).
* `shape` — совпадают набор колонок и число строк (для `take`, где строки произвольны).

Значения нормализуются: real округляется до 6 значащих цифр, datetime приводится к ISO-строке, dynamic — к канонической JSON-строке. Diff возвращает лишние и недостающие строки (до 50 каждой группы) и несовпавшие колонки.
